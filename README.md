# dsh-session-coordinator

DeepSeek Harness 会话协调插件，当前试用版 **0.2.6**。支持独立主会话、总控与多个会话持续协作、一次范围审批覆盖多轮往返，以及忙时在当前轮后续步骤承接回信。

公开试用分支：`share/latest-source`。运行源码与本次本地验收产物一致；不含私人会话日志。尚未上架插件市场，完整产品验收仍在进行。

总控协作、指定发送、群体同步、忙时回信等九类需求及完整示例见[使用手册](./docs/USAGE.md)。

## 安装

首次安装、旧版升级、命令缺失及安装后验证见 [安装手册](./docs/INSTALL.md)。可直接把下面这句话交给 DeepSeek Harness：

> 请按 https://github.com/cxydaizihao520/dsh-session-coordinator/blob/share/latest-source/docs/INSTALL.md 安装或升级 share/latest-source 分支的 dsh-session-coordinator 到 desktop profile，完成构建、打包和版本核验；重启前确认运行中的任务，安装后用手册里的独立会话往返例子验证。

```bash
git clone --branch share/latest-source https://github.com/cxydaizihao520/dsh-session-coordinator.git
cd dsh-session-coordinator
pnpm install --frozen-lockfile
pnpm build
pnpm smoke
pnpm pack
dsh plugin --profile desktop add ./dsh-session-coordinator-0.2.6.tgz
```

需要已安装 DeepSeek Harness（实测 0.2.1-rc.3，最低声明 0.2.1-rc.1）、Node.js 22.18+ 或 24.11+，以及 pnpm。构建工具的 Node 要求高于插件运行清单的最低声明。完成后正常重启 Harness，在插件管理中确认 dsh-session-coordinator 0.2.6 已启用。重启前先处理正在运行的任务。

## 已验证与边界

以下是 macOS Harness 0.2.1-rc.3 的实际桌面旅程，单元/原生测试不代替这些验收。各项注明实际运行版本，不表示后续版本已全部重跑。

| 旅程 | 实际桌面结果 |
| --- | --- |
| 十轮顺序往返（既有桌面样本） | 十轮真实请求/回信完成；一次范围审批，中途没有第三跳拦截或人工逐轮解锁。 |
| 忙时回信及复核（0.2.5） | A 执行约 60 秒的 20 万行扫描，B 的真实回信早于 A 工具结束 53.671 秒；A 同轮后续步骤使用回信合计 101013.15，B 实际复算通过，两个任务及范围完成；零工具错误。 |
| 暂停、恢复与并行（0.2.4） | 暂停商品后，当前原子批次正常结束，运费继续完成后两批；恢复先对账，只执行剩余批次，没有重做已完成批次。 |
| 取消一项、另一项继续（0.2.6） | 两个独立会话同时计算；商品在约 70 秒被原生中断，运费继续至约 108 秒，36 行/1584 验收成功；范围按部分取消关闭。模型先误用一次旧取消工具，被拒后自行改用任务级控制，不能标为零错误。 |
| 重启后恢复（0.2.5 → 0.2.6） | 已扣款至 88、响应未知时退出；重开后 71 秒无自动重放。新人工指令与范围恢复审批后，原会话/任务只补一笔关联原扣款的 +5，余额 93，任务及范围完成；保留中断和旧工具误调用记录。 |
| 重复确认停止（0.2.5） | 四次真实 ACK 后达到无进展上限 3，范围转为预算耗尽，无第五次派工；正常结束后至少 31 秒消息、工具和轮次计数稳定。 |

收信卡使用原生会话名，保留复制与查看来源，移除返回总控及诊断详情。取消错误归属自动上下文的问题已在 0.2.6 修复，并按相同桌面用例复验。

重复的相同结果不会清零无进展计数；变换措辞仍由操作量和时间预算约束。达到上限会停止后续投递，不自动扩容或创建新范围。此机制不代表能识别所有语义循环，也不保证任意外部工具自行结束。暂停允许当前原子工具到安全边界；任务独占运行时可以中断，混合任务保守保留同轮其他工作。模型仍可能先选错旧工具，再自行纠正。

完整附件语义、工作树隔离及全部 Codex 用户旅程未逐项完成验收，不宣称完全等价。以上稳定观察只覆盖对应样本和观察期。

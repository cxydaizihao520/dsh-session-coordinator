# dsh-session-coordinator

把核算、实现和复核交给不同会话，让它们围绕同一任务持续协作，你在原会话接收结果并决定下一步。

本插件参考 **Codex 的独立会话协作设计**：每个参与者有自己的历史，可以在侧边栏单独打开；总控负责派工、审查、返工和收尾。它在 DeepSeek Harness 中实现协作流程，不要求使用 Codex，也不代表完整复刻 Codex 的所有能力。

当前预览版 **0.2.15**。本版已完成隔离原生 web profile 的真实安装与两轮模型协作验收，详见[本版验收](docs/ACCEPTANCE.md)。请以安装后实际版本为准；本版观察不能替代所有模型、平台和用户旅程的验证。

## 用一句话开始

在聊天中说清目标、参与者和完成条件即可。例如：

> 请新建一个独立会话“核算复核”，先计算 17+26，再用另一种方法复核。我核对真实结果后结束协作。只联系这个会话，不读写文件、不安装依赖；本任务内允许自动往返，首次审批后继续。

需要分工时：

> 请组织两个独立会话，一个检查实现，一个审查测试；发现问题就互相反馈、修改和复核，直到这次任务完成。重要范围变更先问我，最后把结果和剩余问题交给我。

首次原生审批会列出目标、成员和预算；批准覆盖当前任务范围，不能自动扩展到其他会话或下一件事。协作工具由模型调用，不需要用户填写会话 ID 或回复参数。

## 能做什么

- **多个独立主会话协作**：复用已有会话或新建会话，跟踪任务与对应结果，支持多轮反馈和返工。
- **忙时承接回信**：结果进入原生安全边界后的步骤，不以收到消息为由取消正在运行的工具。
- **同步信息**：只补充上下文时不唤醒空闲目标；批量发送逐目标报告结果。
- **控制单项任务**：暂停、恢复或取消指定任务；混合任务同轮执行时保守保留无关工作，取消不撤销已发生的外部操作。
- **保留恢复边界**：重开后先检查原操作与副作用，经明确恢复再继续，不盲目重发未知结果。
- **导出协作日志**：会话头部提供导出入口，默认排除正文及原始错误，下载到本机供排障使用，不自动上传。普通人工发送表单已撤下，协作通过聊天发起。

持续协作没有默认固定交接次数，完成、取消、无进展、时间或明确批准的资源预算决定何时停止。旧单次消息仍保留一次任务／回信及两跳保护，不会因升级自动获得持续授权。预算不能由模型自动提高；未知结果应先对账。

## 安装与升级

当前公开源码为 **0.2.15**，npm 包尚未正式发布。已安装 DeepSeek Harness 的用户可从 GitHub 安装：

```bash
dsh plugin --profile desktop add 'git+https://github.com/cxydaizihao520/dsh-session-coordinator.git#main'
```

Git 来源需要安装器构建；遇到 prepare 审批时，只批准安装器显示的本包及准确提交，不全局放行脚本。处理完正在运行的任务后正常重启 Harness，在插件管理中核对版本，并运行上面的核算复核例子。固定提交安装、升级、命令缺失和本地预构建包安装见[安装手册](docs/INSTALL.md)。安装文件存在、工具已注册与真实协作完成是不同的检查项。

最低声明 Harness `0.2.1-rc.1`，本机安装验收宿主为 `0.2.1-rc.5`；其他平台未经本次实机验证。仅开发者从源码构建时，需 Node `22.18+`（22 系列）或 `24.11+`、pnpm `10.30.3`；下面的构建命令在完整源码检出中运行。

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm smoke
pnpm pack
```

公开候选的客户端套件明确跳过八个依赖私人历史记录的回放用例，其余独立用例保留。另有十个依赖私人运行轨迹的审计测试未放入公开默认套件，详见本版验收边界。日志、图片理解、压缩后接手、工作树隔离及并行集成等完整用户旅程仍应逐项验收，不能仅凭工具存在或自动化检查通过宣称与 Codex 完全等价。

更多表达方式见[使用手册](docs/USAGE.md)。反馈到 [GitHub Issues](https://github.com/cxydaizihao520/dsh-session-coordinator/issues)，附版本、脱敏复现步骤和具体错误；不要上传密钥或完整私人会话。

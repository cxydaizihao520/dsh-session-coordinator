# dsh-session-coordinator

DeepSeek Harness 的会话工具插件。用户说明工作目标，Agent 按需查找、读取、新建会话，向一个或多个独立会话发送上下文并取得结果，在已批准的成员和用途内自主协作。

0.2.20 为公开预览版。同一会话内两项原生后台工作分别停止、暂停后的迟到保护和恢复只补剩余，仍待完整桌面验收。已测范围见[验收说明](docs/ACCEPTANCE.md)。

## 安装

从 GitHub 源码安装的命令见安装手册。npm 预览包可用后，在 DeepSeek Harness 插件管理中添加 `dsh-session-coordinator@beta`，或使用 DSH CLI：

```bash
dsh plugin --profile desktop add dsh-session-coordinator@beta
```

源码安装、版本核对及排障见[安装手册](docs/INSTALL.md)。

## 使用

正式交付以在支持的 DSH 标准会话中安装、启用后直接使用为验收条件；用户不需要编辑 YAML、执行初始化命令或另开异步开关。必要权限使用宿主界面确认。自定义会话显式禁用工具或缺少原生作业服务时保留实际限制，不能静默覆盖用户设置。

直接在聊天中说明需求，例如：“让 A 修改、B 测试，反复检查直到交付”，或“新建一个独立会话处理这份对账，结果发回来，我以后还要继续找它聊”。独立会话保留侧边栏入口和自己的历史。Agent 决定分工、何时等待、如何验收，不要求用户填写会话 ID、配对回复或创建编排任务。

发送与创建在缺少相应授权时，通过原生审批明确参与者、用途和操作；已有有效授权直接复用。单条通知不要求回复；需要业务回报时可以批准一次回信；持续协作获批后，成员可在范围内直接互发，无默认固定交接次数。首次可一并批准明确的控制操作，范围内复用；扩大成员、用途或控制范围再确认。通信许可不默认赠送控制权。普通通信无需创建 task 或 Goal，也无需强制关闭步骤。

普通消息默认在空闲时启动处理，忙时在后续安全步骤补充，不打断当前工具。明确要求“等它做完再处理”才排下一轮；纯上下文可保留而不唤醒。发送接纳、模型读到和业务完成是三个不同事实。

需要分别停止后台工作时，由作业所属 Agent 使用 DSH 原生作业工具，确认真实停止及其他工作继续；普通分项停止不要求声明 task 或增加启动包装器。暂停后续派工、修订、定时与恢复只补剩余继续使用按需生命周期保护。

控制沿现有会话工具与原生命令执行，保留对应授权；停止整个当前轮会影响同轮其他工作，后台作业继续使用 DSH 原生界面。聊天头部仅保留日志图标，不增加协作控制工作台。Agent 等待真实输入或原生作业结果，插件不会因任务仍活跃而向原会话自动发送催办消息。

撤销通信许可、撤回未消费消息、停止执行相互独立。已明确批准的控制许可可单独撤销；通信撤权不会顺便取消控制许可。重启不从历史恢复权限；可只读核对旧记录，独立任务须明确恢复。未知结果先核查，不自动换标识重发。

## 工具

完整名称统一以 `session_coordinator_` 开头。

| 核心入口 | 用途 |
| --- | --- |
| `find` | 查找并消歧会话，分页结果明确是否完整 |
| `read` | 读取可见消息及来源；`view=segments` 分页读取完成的输出段，不唤醒目标 |
| `create` | 创建独立主会话；省略 `initialMessage` 可建空白会话，创建与首信分别报告结果 |
| `send` | 用 `targets` 与 `content` 单发或群发；首发、回信共用入口，接纳后返回 |
| `wait` | 按目标游标等待新消息，或按需等待独立任务；结束等待不停止对方 |
| `status` | 查询会话/任务事实；`sessionId + messageId` 只读查询历史回执，不授予新权限 |
| `control` | 分别控制通信许可、消息、执行及按需任务 |

send/create 的接纳回执及 live status 提供完整 `waitTarget`；需要等业务回信时原样使用 send/create 的 `waitTarget`，后续复用 wait 返回的 `cursors`，保留 `replyTo`。历史回执不证明消息仍 pending。`segments`、`message_status` 仅为真实旧聊天保留兼容别名，新聊天使用 read/status。

独立任务、用户问答（`question`）、定时工作（`schedule`）、材料与 Git 工作区等保留为可选扩展；定时不是排下一轮。归档、恢复、监控及只读回执等已有能力按各自权限保留。默认入口收敛不禁用宿主团队或其他正常工具。

旧在途任务按真实旧记录提供兼容入口，执行时继续检查成员、任务状态和版本。新聊天使用上表接口；旧记录不自动获得新授权。涉及历史版本、旧单次回信或旧任务恢复时，请结合对应版本的诊断回执排查。

## 排障与验收

会话头部日志图标下载脱敏 JSON；也可用 `/coordinate logs`，该命令仅为可选排障入口。导出只读，不唤醒会话或重发消息；缺失、截断与未知状态保留。不包含业务正文、文件内容、工作路径或原始错误串，但会话与操作 ID 仍是元数据，分享前应检查。

见[验收说明](docs/ACCEPTANCE.md)。本地测试及原生方法测试不等于真实模型和桌面通过。

## 开发者构建与候选安装

本节供开发和验收使用，普通用户使用已发布包，无需执行下列命令。源码构建使用 Node.js 22.18+（22 系列）或 24.11+、pnpm 10.30.3 和兼容的 DeepSeek Harness；具体版本下限以 `package.json` 为准。从已核对的源码候选构建：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm smoke
pnpm check:compat
pnpm pack
```

安装使用已评审的确切候选包，安装前记录提交与包摘要；版本号本身不能区分本地候选。获得安装与重启授权后，使用官方 CLI，例如：

```bash
dsh plugin --profile desktop add /absolute/path/to/candidate.tgz
```

正常重启后记录实际加载证据并核对产物指纹，再只在批准的测试范围运行旅程。旧源码分支与历史安装命令不代表当前候选。

宿主产物为 `lib/index.js`，客户端产物为手写的 `src/client/index.js`；客户端由 `scripts/test-client-bundle.mjs` 回归覆盖。DSH 升级后须重新构建并核对兼容性；与宿主共享的单例依赖由构建配置保持外置。
